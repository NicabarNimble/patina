**Key decisions:**
- Discovered OS sandboxes (SBPL, Landlock) cannot filter by hostname — only port/IP. The manifest `domains` field was unenforced. This is not "future work" — it's a security gap.
- Decision: mirror WASM `host_http_request` pattern for native children. Children call `pipe/http` over stdio, Mother checks domain, makes HTTP call. OS sandbox blocks ALL direct sockets.
- Created [[spec-pipe-mother-io]] to own the fix. Build order: pipe-mother-io blocks github-connector and mother-broker. No connector ships until domain enforcement works.
- Rejected over-engineered "Mother I/O Service" proposal (multi-language SDKs, gRPC, capability descriptors). Shipped lean spec: one `pipe/http` RPC, one helper, one sandbox tightening.
- `--no-sandbox` opt-out scoped to [[spec-mother-broker]], not pipe crate. Error messages updated to not promise features that don't exist.

**Challenges:**
- Other agent prematurely updated specs to describe deny-all sandbox (code still allows 443/53). Caught and corrected: specs must describe current code, with forward references to pipe-mother-io for tightening.
- Spec wording was too GitHub-specific in pipe-mother-io. Fixed to be provider-agnostic — pipe/http serves GitHub, Google Workspace, Slack, any REST API.

**Patterns observed:**
- Fork-based testing (fork, apply irrevocable sandbox, test, report via pipe) is the correct pattern for testing irrevocable OS enforcement. Used identically on both macOS and Linux.
- Specs that describe aspirational state as current state are lies. Every spec should say what the code does NOW, with explicit forward references for what changes later.
- Testing platform-specific code catches real bugs: 5 bugs found across 2 sessions by actually running cfg-gated code.
