`forge.*` — the github-connector emits `github.*`."

[[commit-f4180f3d]]: Added `priority` column to `schema_registry`. Schemas with `[[contracts]]`
declarations get priority=1 (active connector), schemas without get priority=0 (legacy/read-only).
`resolve_event_type()` now sorts `ORDER BY priority DESC, schema_name ASC` — active connectors
win, with alphabetical tiebreaker within same priority tier.

- `github` schema has `[[contracts]]` + `[[projections]]` + `[lake]` → priority=1
- `forge` schema has none of these → priority=0
- Result: `resolve_event_type("forge_issues", ...)` now returns `github.issue`

**Key decisions:**
- Used `[[contracts]]` presence as the discriminator for active vs legacy. This is structural —
  a schema declaring contracts is explicitly claiming it's the authoritative writer for those
  fact types. No hardcoded schema name checks.
- Idempotent `ALTER TABLE ADD COLUMN` migration for existing schema_registry tables.
- Added explicit test (`test_resolve_event_type_priority_over_alphabetical`) that verifies
  a priority=1 schema beats a priority=0 schema regardless of name ordering.
