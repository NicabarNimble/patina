## Previous Session Context
Closed all 8 testing gaps from pipe-native-transport: found and fixed 2 real macOS `apply_sandbox()` bugs (wrong `sandbox_init()` flag, invalid SBPL syntax), fixed Landlock ABI detection, replaced external network dependency in tests with loopback, and added fork-based enforcement tests on both platforms. Critically, discovered that OS sandboxes (SBPL, Landlock) cannot filter by hostname — only port/IP — meaning the manifest `domains` field was unenforced. Created [[spec-pipe-mother-io]] to solve this: children call `pipe/http` over stdio, Mother checks domain allowlist and proxies the HTTP call, while OS sandbox blocks ALL direct sockets. This spec blocks github-connector and mother-broker — no connector ships until domain enforcement works.

**Key decisions:**
- Named it `PipeIo` not `MotherHttpClient` — combines fact emission AND HTTP in one context. Better name since fetch() needs both capabilities, not just HTTP
- `HttpHandler` is a callback (`Box<dyn FnMut>`) so patina-pipe doesn't depend on reqwest. Caller provides the handler — production Mother uses reqwest+domain checking, tests use mock
- pipe/http request IDs start at 10000 to avoid collision with Mother's request IDs (which start at 1). Both share stdout but IDs distinguish by presence of `"method"` field (requests vs responses)
- Removed `system-socket` from macOS profile along with `network-outbound` — children need zero socket operations

**Challenges:**
- Bidirectional protocol during fetch: child writes pipe/http requests on stdout (same channel as pipe/fact), reads responses from stdin (same channel Mother uses for pipe/fetch). Solved by distinguishing messages by `"method"` field presence and refactoring run() to read_line() loop
- reqwest dependency: can't add to patina-pipe (would bloat child binaries). Solved with HttpHandler callback pattern
