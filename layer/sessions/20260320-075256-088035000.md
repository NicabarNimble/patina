**Discussion context:**

Session started with user noticing an active session already existed without explicitly starting one. This led to a three-part investigation:

**1. Auto-start discovery:** Traced the `check_in()` function in `src/interface/internal/checkin.rs` — when `patina ai launch` runs, it looks for an existing active session for the adapter, and if none exists, auto-creates one via `session::begin_session()`. This was introduced on **2026-03-11** in [[commit-85f73900]] (`refactor(interface): separate native projection ownership`), with the launch surface wired in [[commit-ed11bd2f]] (`refactor(ai): collapse setup to one surface`).

**2. Comprehensive session audit:** Read all 35 session files created since Mar 11 to analyze format evolution and quality. Identified three format eras:
- Era 1 (pre-Mar 11): plain `YYYYMMDD-HHMMSS`, no runtime metadata
- Era 2 (Mar 11–14): 4-char random suffix (EF79, RYYL, etc.), full participants/runtime metadata
- Era 3 (Mar 16+): nanosecond timestamps replacing 4-char suffix, new end_tag variants (`-tmux-lost`, `-superseded`)

**3. Ghost session problem identified:** 17 of 35 sessions (~50%) are "ghosts" — auto-created by `check_in()`, never engaged by a human, auto-archived with empty bodies. Key symptoms:
- Title: always generic (`"claude session"`, `"opencode session"`)
- `display_name`: interface name (`claude`) instead of user name (`nicabar`)
- Previous Session Context: unfilled template comment
- Body: completely empty except auto-archive handoff boilerplate
- These break the continuity chain between real sessions

**End tag taxonomy discovered:**
- `-end` (14 sessions): clean `/session-end`
- `-tmux-lost` (11 sessions): lane died from Mac sleep/crash
- `-superseded` (5 sessions): another runtime claimed the lane

**Patterns observed:**
- Auto-start is a ghost session factory — every MCP server boot creates one
- Signal-to-noise ratio in session history is ~50% due to ghosts
- User-started sessions (`display_name: nicabar`) have rich content; auto-started ones don't
- The `role` field shifted silently from `operator` to `interface` with no migration
- The `llm` field is misleading — stores interface name, not LLM backend

**Discussion context:**

Continued from the session audit findings into design direction. Key progression:

1. **Auto-start + update = usable session**: Demonstrated that `/session-update` can rescue a ghost session's body, but frontmatter identity (`display_name`, `title`) remains auto-created and immutable from the skill layer.

2. **Git tag integrity gap discovered**: End tags `-tmux-lost` and `-superseded` are written to session frontmatter `end_tag` field but **never actually created as git tags**. Only clean `/session-end` creates real end tags. Orphaned start tags with no corresponding end tags exist throughout the history.

3. **Operator design direction crystallized**: Universal artifact format, interface-specific creation. Each interface handles how artifacts get populated based on its persistence model. `/session-start` becomes enrichment (title/goal injection) not creation. WASM child interface helper spawned at Mother handshake for durable artifact writing.

4. **`session-handoff-enrichment` disposition**: Operator leaning toward absorbing core pieces (`parent_session`, `<modified-files>`, structured handoff) into [[spec-interface-session-model]] and potentially abandoning the rest. Spec was written before auto-start and interface-specific needs were understood.

5. **Prior session context surfaced**: Found [[session-20260318-221008-061837000]] which had the full session redesign discussion — sessions as interface logs, OpenCode vs Claude persistence models, proposed `ChildType::Interface`. That thinking feeds directly into this spec.

**Key decisions:**
- Session artifact format stays universal — same YAML frontmatter, same markdown body, same git tags across all interfaces
- Each interface owns HOW the artifact gets enriched based on its persistence capabilities
- WASM child interface helper is the architectural centerpiece for crash resilience
- Git tags must be real for all end states (current `-tmux-lost`/`-superseded` are frontmatter-only — a bug)
