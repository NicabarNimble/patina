3. **AC 6: Status shows children health** ([[commit-28846108]]) — Extended `HealthResponse` with `children: Vec<ChildHealthJson>` (name + status string via `ChildHealth::Display`). Updated `HealthInfo` and `show_status()` in `src/commands/mother/mod.rs` to parse and display children. Added `#[allow(dead_code)]` on `unload_all()` (legitimate lifecycle method, can't be called from signal handlers). Live-tested: `/health` JSON includes children array, `patina mother status` displays "Children: secrets: healthy".

**Key decisions:**

- **Path parsing via split, not regex** — `/child/{name}/{action}` is simple enough for string splitting. No new dependencies, no complexity.
- **404 for unknown children, not 500** — `handle_child_request()` returns 404 when `registry.handle()` fails on unknown child name. Makes semantic sense: the resource doesn't exist.
- **`ChildHealth` serialized via Display, not Serialize** — Avoids adding `Serialize` derive to the library crate type. The `Display` impl already exists and produces clean strings ("healthy", "degraded: reason", "unhealthy: reason").
- **`#[serde(default)]` on `children` in `HealthInfo`** — Backward compatibility: if an old daemon doesn't return `children`, deserialization still works.

**Challenges faced:**

- **Backgrounding daemon in bash** — `patina mother start &` in compound bash commands caused shell parsing issues (subsequent commands parsed as sleep arguments). Solved by using `run_in_background` parameter for the daemon and running tests separately.

**Patterns observed:**

- **Anchoring in core values before coding catches design drift** — Reading [[dependable-rust]], [[unix-philosophy]], [[spec-driven-design]] before starting ensured clean boundaries: library types stay in `src/mother/`, command implementation stays in `src/commands/mother/`, no leakage.
- **One AC = one commit** — Clean separation. Each commit stands alone and can be reviewed independently.
- **Live testing catches what compilation doesn't** — AC 4 and AC 6 were verified with `curl` and `patina mother status` against the running daemon. Build-only verification would have missed integration issues.
