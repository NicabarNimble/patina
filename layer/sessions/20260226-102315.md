**Key decisions and reasoning:**

- **Events.db is the project's autobiography, not ops telemetry.** Kleppmann/Schickling
  insight: the event log should capture every meaningful moment (belief creation, spec
  transitions, decisions), not just tool timings. layer/ markdown files are human-readable
  projections of current state; events are the history. This makes events.db irreplaceable
  and the durability question much more real.

- **Belief layer = emergent patterns + named decisions (Layer 3).** Proto-beliefs
  (SAE features, concept clusters) and named beliefs are the same layer at different
  maturity stages. New computational methods (SAEs, graph neural nets) don't add layers
  — they add inputs to Layer 3. The belief layer is the integration point.

- **Mother is core, not optional.** Every patina installation has mother. She manages
  federation, connector registry, and reference repos. Projects are sovereign but
  mother is always present.

- **Git is the one source.** src/, layer/, .git/ are not separate sources — they're
  directories in a git repo. Connectors (WASM, mother-managed) provide enrichment
  from external APIs. Forge is connector #1, not a special case.

- **Event governance: registry-first, doctor-enforced.** The spec's event type table
  IS the canonical registry. Forward-compatible JSON (additive fields only). Doctor
  audits emission coverage. No ad-hoc event types.

- **Federation identity: (source, id) composite key.** Semantic similarity for
  cross-project discovery, not ID matching. Sovereignty over reconciliation —
  mother reports divergence, never judges.
