**Key decisions:**
- patina-metal should not remain as a crate. Routing infrastructure (Metal enum, extension mapping) folds into patina-ai. Grammar implementations become plugins.
- Grammar extraction design is parser-agnostic — pipeline `handle()` doesn't care if the plugin uses tree-sitter, cairo-lang-parser, or anything else. Each plugin bundles its own parser version, permanently solving version conflicts.
- Version conflict hell (tree-sitter 0.23 vs 0.24 "links" conflicts from session [[20250901-135830]]) is structurally impossible with plugins — each bundles its own deps.
- Cairo is pure Rust — should compile to wasm32-wasip2 natively (no wasi-sdk needed). Validates non-tree-sitter parser plugin path.
- crates.io name `patina` is taken by UEFI SDK. Low confusion risk — they use underscores (`patina_*`), we use hyphens (`patina-*`). Grammar plugins won't be on crates.io at all (WASM binaries via `patina plugin install`).
- Revised previous update: two crates on crates.io (`patina-ai`, `patina-sdk`), not three. `patina-metal` goes away entirely rather than being published.
