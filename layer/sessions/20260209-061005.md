### 06:52–07:30 — Phase 5c: Training stability — SPEC + implementation (2 commits)

**Work completed:**
Read-first discipline: `src/commands/oxidize/mod.rs`, `src/commands/oxidize/commits.rs`, `src/commands/oxidize/temporal.rs`, `src/commands/oxidize/dependency.rs`, `src/commands/oxidize/trainer.rs`, `src/commands/oxidize/pairs.rs`. Investigated all sources of randomness, analyzed available training data pool via SQL queries against patina.db.

**Root cause analysis:**
`num_pairs = 100` in `train_projection()` samples 18% of 551 viable commits. Per [[andrew-ng-over-shoulder]]: "A fixed seed doesn't reduce variance — it hides it." With 100 pairs from 551+ available, we're in a high-variance regime. The data pool is small enough to use entirely: 551 commit pairs, 800 temporal pairs, 8,262 dependency pairs — all trivial to embed and train on CPU. Cargo-culted sampling from large-scale ML where it saves memory/time; here it saves ~2 seconds and costs ±15pp P@10 stability.

**Also found:** the sampling pattern exists ONLY in training pair generators, not in corpus builders. `query_knowledge_corpus()`, `query_session_corpus()`, `query_file_events()` all use ALL available data. The mismatch: we index everything but learn from 18%.

**SPEC amendment ([[acd5b092]]):**
