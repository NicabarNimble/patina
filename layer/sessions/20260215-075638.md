### 08:20 - Exploration Questions Answered
Answered all 6 exploration questions from [[knowledge-protocol]] spec:

**Q1: Does content addressing work for beliefs?** No. Belief identity is the slug, not the hash. Beliefs are meant to be mutable — evidence accumulates, entrenchment shifts, relationships form. A hash changes on every edit, creating meaningless object churn.

**Q2: Hash function?** Moot — content addressing rejected.

**Q3: How does scrape find objects?** Today's glob of `layer/surface/epistemic/beliefs/*.md` is simpler and correct. Walking refs would add N+1 syscalls for no benefit.

**Q4: Migration path?** Not needed — no migration.

**Q5: Graph store?** Yes, independently of substrate question. `belief_edges` table in SQLite would make relationship graph queryable. Enhancement to scrape, not a new filesystem.

**Q6: Subsume belief-mechanics?** No dependency. Belief-mechanics is about status management, not storage.

**Critical realization:** Every proposed service maps to an existing git primitive. Session tags and release tags already ARE knowledge refs. The only genuinely missing capability is `patina diff` — implementable with `git2` + frontmatter parser, no filesystem changes.
