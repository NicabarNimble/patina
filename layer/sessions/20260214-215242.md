Copies `plugin.wasm` + `plugin.toml` from `grammar-*/target/wasm32-wasip2/release/` to `~/.patina/pipeline/grammar-<name>/`. Supports `--list`, `--only`, `--force`. - **Phase 6**: Built `patina bench grammar` command. Profiles WASM pipeline plugin throughput with three measurements: discovery time, engine creation cost, and per-file dispatch latency. Tests both per-call (fresh engine) and shared engine modes. Added `Grammar` variant to `BenchCommands`.
- Updated [[grammar-extraction]] SPEC.md — checked off both Important exit criteria, added status log entry.

**Key decisions:**
- Abandoned compiled-in A/B baseline. `RustProcessor::process_file()` fails with "Failed to set Rust language" — tree-sitter 0.24.7 vs tree-sitter-rust 0.24.0 version conflict. This is precisely the version hell that WASM extraction was designed to eliminate. The broken baseline *is* the proof that WASM plugins are the right architecture.
- Pivoted Phase 6 from "compiled-in vs WASM overhead ratio" to "WASM throughput profiling" — measures what's actionable (where time goes in WASM dispatch) rather than comparing against a broken baseline.
- Kept grammar defaults as a const array in `grammars.rs` rather than parsing `grammar-defaults.toml` at runtime — simpler, no toml parsing dependency needed for this path. The TOML file exists as documentation/source-of-truth for tooling.

**Benchmark results (232 Rust files):**
- Per-file latency: 3.1ms/file (326 files/s)
- Engine creation: 0.04ms (negligible)
- Shared vs per-call engine: 1.0x (no benefit to reuse)
- Discovery overhead: ~3s one-time (loads all 9 plugin WASM components)

**Challenges faced:**
- Compiled-in RustProcessor broken by tree-sitter version mismatch. Since grammar-rust WASM plugin has been handling all .rs files since Phase 2, this went unnoticed. User correctly identified this as a non-issue — "we're fully committed to WASM now."
