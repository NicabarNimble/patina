Three iterative commits driven by two rounds of external audit:

1. [[commit-e089745d]]: Initial migration — replaced two hardcoded functions with schema-driven
   loop reading `IndexConfig.table` and `FactDef.event_type` from installed schemas. 5 unit tests.

2. [[commit-bb92d940]]: Audit P1/P2/P3 fix — added shared-table dedup via HashSet (P1: two schemas

   expanded to 15 tests covering the actual regression surface (P3). Added stale entry cleanup
   for skipped event_types.

3. [[commit-cf3f9ae2]]: Deterministic schema sort — `schemas.sort_by(name)` before the first-wins
   dedup loop so shared-table label assignment is not `read_dir()`-order-dependent. `forge` now
   wins alphabetically, matching legacy `LIKE '%.issue'`/`LIKE '%.pr'` search patterns.

**Key decisions:**
- Chose FTS5 as first consumer: simplest isolated consumer, small blast radius, proves read-side
  contract model works. The write-side (`insert_issues`/`insert_prs`) is a harder migration
  with real data consequences — deferred to next session.
- Did NOT extract schema types to a neutral module. The cross-command dependency
  (`commands::scrape` → `commands::schema::load_all_installed()`) already exists at line 101.
  No point creating indirection for a dependency that's already established.
- Content built from declared `fts_fields` filtered to available columns, not hardcoded `body`.
  Falls back to `body` when no fields resolve — backward compat.

**Challenges:**
- First commit had three correctness problems caught by external audit: (1) shared tables
  indexed twice producing fabricated labels, (2) `fts_fields` contract ignored, (3) tests
  only covered the helper not the real code path. All three were genuine — the initial migration
  replaced hardcoded strings with schema lookups but didn't remove forge-era assumptions underneath.
- Stale FTS entries: dedup prevents new INSERT but doesn't clean old entries from previous runs.
  Required explicit DELETE for skipped event_types after the dedup loop.
- Label ordering: `read_dir()` order is filesystem-dependent. Fixed with alphabetical sort.

**What the audit identified as next work (NOT this session):**
- Write-side migration: `insert_issues()`/`insert_prs()` still hardcode `"forge.issue"`/`"forge.pr"`
  event types. Changing these has real data consequences (new events labeled `github.*`).
- DDL rename: `forge_issues` → `github_issues` governed by [[spec-connector-owns-tables]].
- Frozen WASM path in `host_support.rs` for forge plugin direct-write.
