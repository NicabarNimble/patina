### 07:54–11:51 — Phase 5c: Validate Training Stability (2 commits)

**Work completed:**
Read-first discipline: [[semantic-structural-split]] SPEC, [[spec-driven-design]], [[dependable-rust]], [[unix-philosophy]], `src/commands/oxidize/mod.rs`, `src/commands/oxidize/commits.rs`, `src/commands/oxidize/temporal.rs`, `src/commands/oxidize/dependency.rs`, `src/commands/oxidize/trainer.rs`, `src/commands/oxidize/recipe.rs`, `src/embeddings/onnx.rs`.

Ran second `patina oxidize` — checksums didn't match first run. Investigated and found **5 additional non-determinism sources** beyond the seed fix from previous session:

1. **HashMap/HashSet iteration order** — `temporal.rs:59`, `dependency.rs:60`, `commits.rs:58` collected from HashMap iterators with random ordering. Fixed: sorted all collected vecs.
2. **SQL queries without ORDER BY** — `query_all_functions()`, `query_commit_files()` returned non-deterministic row order. Fixed: added explicit ORDER BY.
3. **Recipe projection iteration** — `recipe.projections` is a HashMap, projections trained in random order each run. Fixed: sorted alphabetically.
4. **Safetensors metadata HashMap** — `trainer.rs` serialized metadata via HashMap, causing different JSON key ordering in headers. Fixed: removed metadata (dimensions encoded in tensor shapes).
5. **ONNX Runtime threading** — even with `with_deterministic_compute(true)` and `with_intra_threads(1)`, inter-op parallelism caused non-deterministic graph execution. Fixed: added `with_inter_threads(1)`.

Each fix was discovered iteratively by running oxidize pairs and comparing checksums. The investigation required ~8 oxidize runs total before achieving perfect determinism.

**Determinism fix ([[6c8c790a]]):**
6 files changed (+37/-32). All 4 projections now produce identical md5 checksums across consecutive runs.

**Scry eval results:**
P@10 9.2%, hit rate 15%, 3/20 scry-only hits. Significant regression from Phase 5a baseline (44.2%). The 44.2% was a high-variance outlier from random 100-pair sampling. Training loss barely decreases (0.1677 across 10 epochs) — the commit-function triplet strategy produces weak contrastive signal.

**SPEC update ([[fb934270]]):**
Phase 5c exit criteria all checked. Results and root cause analysis documented. Training signal quality identified as future work for Phase 5d+.

**Key decisions:**
- ONNX single-threaded: accepted the performance cost (embedding is slower) for deterministic projections. Training pipeline runs occasionally, not latency-sensitive.
- Removed safetensors metadata: the dimensions are already encoded in tensor shapes, metadata was only used for inspection. Determinism > convenience.
- Documented P@10 regression honestly per [[andrew-ng-over-shoulder]]: the 44.2% was never real — it was the best of a high-variance distribution.

**Challenges faced:**
- 8 oxidize runs (each ~5 minutes) to isolate 5 non-determinism sources iteratively
- HashMap non-determinism was the hardest to find — losses appeared identical (same 4-decimal values) but checksums differed. Root cause: tiny float differences from ONNX threading below the loss reporting threshold but visible in binary weight representation.
- Had to distinguish metadata serialization non-determinism from actual weight non-determinism using Python to inspect safetensors headers.

**Patterns observed:**
- [[dependable-rust]] validated: all fixes were internal to oxidize/embeddings modules, no public interface changes
- Non-determinism in ML pipelines has multiple layers: data ordering, algorithm, serialization, runtime — each must be addressed independently
- HashMap is a non-determinism landmine in any reproducibility-sensitive code path — should audit all uses in training/serialization pipelines
