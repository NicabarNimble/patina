**Key discoveries (wasmtime-wasi v41 + wit-bindgen 0.41):**
1. `wit_bindgen::generate!` with `export!` macro must live at crate root — `mod wit { generate!() }` causes `export!` to fail with "could not find `export` in the crate root"
2. `generate_all` flag required for imported interfaces — without it, `patina:host/log` needs explicit `with:` mapping
3. `MotherChildPlugin: Default` makes trait not dyn-compatible — removed Default from supertrait, macro enforces it at call site
4. wasmtime-wasi v41: types at `wasmtime_wasi::` root (not `::p2::`), `WasiView::ctx()` returns `WasiCtxView<'_>` (combined ctx + table struct), no separate `table()` method
5. `#[link_section = ".patina_api_version"]` crashes LLVM on macOS (Mach-O requires `segment,section`) — gated with `#[cfg(target_arch = "wasm32")]`

**Pattern: Zed-exact plugin architecture works**
The Zed extension_api pattern translates cleanly to Patina:
- API crate owns `generate!` + Component + Guest impl + `export!`
- Plugin crates just implement trait + call `register_plugin!`
- `init` export for explicit initialization (no constructors, no lazy-init complexity)
- Type conversion between trait types and bindgen types handled in Component impl
