### 09:15 - Lake Architecture Vision + Proving Slice
User shared 3-zone lake model:
- **Raw:** append-only connector output, Parquet, immutable capture, connector-owned
- **Curated:** shared tables from raw, DuckLake first backend, Iceberg-replaceable
- **Serving:** local Mother/project projections, indexes, caches

Key implication for [[spec-connector-owns-tables]]: lake scope for connectors means raw Parquet output, NOT "SQLite at a different path." This makes the proving slice much stronger:
- `materialize("project", ...)` → denormalized SQLite tables (upsert/dedup)
- `materialize("lake", ...)` → raw Parquet files (append-only, immutable)
- Genuinely different operations sharing domain logic — validates scope-switching model

User established discipline: "We are not shrinking the product to an MVP. We are defining a smaller proving slice of the full product."
