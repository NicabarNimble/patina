### 08:20-09:00 - Phase 1: Fix the Feedback Loop (F1)

**Goal:** Find why `patina eval --feedback` returns 0% precision across 2,652 retrievals.

**Data flow trace:** Read [[eval-repair]] spec, then traced retrieval→commit linkage:
- Retrieval events: `scry.query` in eventlog (`src/commands/scry/internal/logging.rs`)
- Commit events: `git.commit` in eventlog (`src/commands/scrape/git/mod.rs`)
- Linkage: SQL views in `src/eventlog.rs` join on `session_id`

**Root cause: 4 bugs found and fixed** [[commit-38acca48]]:

1. **Session ID format mismatch (CRITICAL — caused 0%):** `parse_session_tags()` extracted `20260207-081654-claude` from tags (with adapter suffix), but `get_active_session_id()` reads `20260207-081654` from YAML (no suffix). The JOIN on `session_id` produced zero overlap across 19 sessions that should have matched.

2. **ROW_NUMBER dedup dropped files:** `PARTITION BY sha` in `feedback_commit_files` view meant `json_each` rows (one per file) got different row numbers — only 1 file per commit survived. Fixed: `PARTITION BY (sha, file_path)`.

3. **doc_id `::` suffix broke matching:** SemanticOracle doc_ids like `src/main.rs::fn:main` don't substring-match `src/main.rs`. Fixed: strip `::` suffix and `./` prefix before matching.

4. **Git rename paths stored raw:** numstat `{old => new}` format never matches scry doc_ids. Added `resolve_rename_path()` to extract destination path.

**Performance fix:** Replaced slow correlated EXISTS subquery in `feedback_query_hits` view with materialized temp tables + LEFT JOIN. Eval completes in seconds instead of hanging.

**Results:** 0% → **2.2% overall, 5.5% rank 1, 11.3% best session** (19 sessions with overlap)

### Patterns Observed

- **Hub file pollution:** `src/commands/mod.rs` (importance=28) appears in 14/20 NL queries at ranks 1-2. High co-change count makes temporal oracle a magnet that drowns specific files. This is the F3 fusion dilution problem.
- **Belief oracle over-reach:** Beliefs transitively project `spec/internal.rs` and `spec/mod.rs` into unrelated queries. The linkage is too broad — beliefs connecting to a file doesn't mean that file answers every query mentioning belief concepts.
- **Core docs invisible for concept queries:** `layer/core/dependable-rust.md` doesn't appear for "what is the dependable rust pattern." Core `.md` files in `layer/` underperform against code files with higher temporal/lexical scores.
- **Multi-term queries dilute FTS5:** 4+ term queries produce flat 0.016 score ties from OR-expansion. The lexical oracle loses focus.
- **Session ID format was a latent integration bug:** `session start` writes tags with adapter suffix, `session start` writes YAML id without suffix. Two systems encoding the same entity differently. [[fix-data-not-tools]] applied — the data format mismatch was the bug, not the tools.
