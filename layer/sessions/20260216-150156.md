**Key decisions:**
- **Transactional rebuild, not incremental update** — `sync_knowledge()` does
  `BEGIN→DELETE all→repopulate→COMMIT`. Simpler than tracking deltas, and knowledge
  is a rebuildable cache. Per SPEC: "CLI/MCP queries during sync see either the old
  complete state or the new complete state, never partial."
- **Current project needs separate collection path** — `registry.projects` is empty
  for projects that were never `patina repo register`'d. The auto-detect path
  (`find_project_root()`) must also collect beliefs. Discovered during exit criteria testing.
- **FTS5 JOIN for ranked results** — `search_knowledge()` joins `knowledge_search`
  (FTS5 virtual table) with `knowledge` (regular table) to get all fields while
  preserving FTS5 rank ordering. Simpler than external content tables.
