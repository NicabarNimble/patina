   `None` return from the logging function, silently dropping the entire event when

4. **Added context/assay usage events (gaps 5-6)** ([[commit-9e92b1fd]]): CLI paths
   wrap execution with `Instant::now()` timing, emit via `eventlog::insert_event()`

5. **Added doctor emission coverage** ([[commit-4ae2e726]]): `ACTIVE_EVENT_TYPES`
   const lists 12 registered Active types. Runtime check: `COUNT(*)` per type in
   events.db. Reports coverage percentage and missing types. Warning, not failure.

6. **Retargeted session events to events.db** ([[commit-96e59ce7]]): `session.started`,
   `session.update`, `session.ended` were writing to patina.db (rebuildable). Fixed
   to use `open_events_db()` (irreplaceable). This was NOT in the spec's 7 gaps but
   was exit criteria 5 — discovered by reading actual code, not assuming.

**Key decisions:**
- Used `emit_or_warn()` for scrapers (non-fatal) but direct `insert_event()` for
  context/assay (matching scry's best-effort pattern with explicit warning on failure).
- Context/assay events are NOT measure verbs — they use `eventlog::insert_event()`
  directly because `context.query` and `assay.query` aren't in `VALID_VERBS`.
- Extracted `execute_inner()` in assay to wrap timing around the full function without
  restructuring all the early-return branches.
- WASM doctor plugin takes priority over bundled doctor — emission coverage check
  works in bundled but needs WASM plugin rebuild to surface in production.

**Patterns observed:**
- "Read before write" principle caught the session event retargeting bug — the spec
  said "verify, don't assume" for exit criteria 5, and indeed the events were going
  to the wrong database.
- The `?` operator on `Option` in a function returning `Option` is a silent swallower —
  it returns `None` from the function, not an error. This made scry logging silently
  do nothing when no session was active. Non-obvious bug hiding in plain sight.
