**Key decisions:**
- **Agency test for classification**: Children make decisions (retry, cursors, failure handling). Toys do work when asked (fetch, store, proxy). Connectors are toys, not children. DuckLake is a child.
- **Approved toys model**: Mother grants toy approvals at init time. Child uses them independently. No handoff, no per-request mediation. Mother is out of the data path.
- **pipe/initialize is a security boundary**: The init payload carries the full capability token set. It is no longer just startup config.
- **Option C for protocol shape**: Initialize carries everything, child reads what it needs. Add `pipe/run` for children with agency.
- **Branch before spawn in broker/mod.rs**: `Destination::Project` spawns connector (Mother drives). `Destination::Lake` spawns lakehouse child (child uses approved toys). Two completely different spawn paths.
- **Runtime is orthogonal**: WASM is long-term vision, native is fine now. Design interfaces as if they'll become WIT boundaries.

**Discussion with audit agent (4 rounds):**
- Round 1: Agent confirmed 5 gaps, flagged protocol/config mismatch as bigger than just pipe/run
- Round 2: Agent reordered priorities (resolve Gap 3 first, then protocol shape, then design docs)
- Round 3: Agent separated agency axis from runtime axis — "don't lock children to WASM"
- Round 4: Agent endorsed "approved toys" model, cautioned to keep capability model coarse and explicit

**Patterns observed:**
- "Read code before write code" paid off immediately — Gap 3 (spawn path mismatch) would have been a costly mid-implementation discovery
- The architectural model evolved through conversation: handoff → capability grant → approved-use. Each iteration made Mother's role cleaner.
- Audit agent as external reviewer is extremely effective for catching merged concepts (agency ≠ runtime)
