### 13:15–13:45 - VCS evaluation: git worktrees vs jj
- **jj (jujutsu)**: Lock-free concurrent writes via operation log, first-class conflicts, auto-snapshotting, workspaces. Colocated mode keeps `.git/`. Pre-1.0 (v0.38).
- **Decision: stay with git.** Worktrees solve isolation without new deps. Concurrency gaps fixable with Mother DB transactions. jj's best feature (conflict recording) sidestepped by worktree isolation.

### 13:45–14:00 - CRDT + iroh evaluation
- **CRDTs**: Not needed for code (worktrees isolate), but natural fit for session metadata — activity logs, participants, beliefs, spec status. Existing data is already CRDT-shaped (append-only, agent-partitioned).
- **iroh**: P2P networking stack by n0. Overkill for local multi-process, but the right transport for multi-machine Mother sync.
- **Decision: design CRDT merge semantics alongside worktree work** so iroh plugs in later with no rework.

### 14:00 - Converged architecture
Three-layer design where steps 1+2 ship together:

1. **Agent isolation**: git worktrees per session, one branch per agent
2. **CRDT discipline in Mother DB**: Every write gets `(runtime_id, hlc_timestamp)`. No UPDATE, only INSERT. Status changes as event log. Deletes as tombstones. Schema becomes the sync protocol.
3. **Transport (future)**: iroh for multi-machine Mother sync. Sync = "send rows where `hlc_timestamp > last_sync`". No custom wire protocol.

Key principle: steps 1+2 together so schema is sync-ready before iroh arrives.

## Decisions
- **Stay with git** — worktrees for agent isolation, no jj. jj is a better VCS but adding a pre-1.0 dep to control our own stack is wrong timing.
- **CRDT discipline now, CRDT library never** — encode domain merge rules (G-Set for beliefs, LWW-Register for status, append-only logs) directly in schema design. No automerge/loro dependency.
- **iroh as future transport only** — not for local IPC (SQLite + filesystem already work). Enters when Patina goes multi-machine.
- **Steps 1+2 ship together** — worktree isolation + CRDT-ready schema in one pass. Every write tagged with `(runtime_id, hlc_timestamp)`. No UPDATE, only INSERT. This prevents rework when iroh arrives.
