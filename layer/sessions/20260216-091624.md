Key insight emerged at session end: mapping all measurement tools against [[patina-identity]]'s five protocol verbs (capture, index, search, believe, evolve) revealed that measurement concentrates on **search** and **believe**, while three verbs have zero measurement coverage: **capture**, **index**, and **evolve**. **Key decisions:**
- **Events-only for measure** — `patina measure` never reads materialized tables (beliefs, function_facts) directly. Producers snapshot summaries into measurement events. This keeps the contract uniform across all verbs and makes history/replay free.
- **Two views, one command** — `patina measure` (default) shows project health in natural language. `patina measure --system` shows raw metrics, history, regression detection. Not two commands — one command with audience-appropriate output.
- **Plugin measurement via WIT** — new `patina:host/measure@0.1.0` interface. Plugins call `record-measurement(verb, tool, mode, metrics_json)`. Host validates and stores. Doctor is the proof-of-concept migration.
- **[[belief-truthfulness]] as design template** — the measurement system generalizes the pattern that belief audit already implements for the believe verb. Three-level hierarchy: system view → verb detail → item detail.
