### 08:30 - Data architecture discussion
Deep discussion on data design: identified that patina.db conflates irreplaceable history
(measure.*, forge cache) with rebuildable cache (code structure, git commits). Identified
the eventlog is not truly append-only — scrapers use DELETE+INSERT. Discussed event-sourcing
patterns from "big boy" systems (Twitch, Netflix): event stream → consumers → materialized
views, all automatic. Key insight from user: the visualization is secondary — the real
primitive is making data queryable by a local LLM. Model-swap requirement means MCP tool
calling is the right interface.
