### 07:45-08:15 - Root Cause: The Mixing Problem
Discovered that scry and assay were INTENDED to be split along
semantic/structural lines but scry absorbed everything. Explored
current architecture: assay owns call graphs and module signals,
scry owns 5 oracles (semantic + lexical + temporal + persona + belief)
plus 3 FTS5 tables plus RRF fusion.

Traced 6 sessions of retrieval tuning problems back to this mixing:
- BM25 scale mismatch: 3 FTS5 tables with different column counts
  in one pipeline — directly caused by mixing
- P@5 fusion dilution: non-semantic oracles inserting results via
  RRF — directly caused by mixing
- 25-parameter tuning trap: 5 oracles × 5 intents — complexity
  from balancing meaning + facts in one step
- Semantic index pollution: 27K items (88% session events) in one
  vector space — everything dumped together
- Non-isolable debugging: every fix cascaded through shared pipeline

The bugs were independent (eval math, doc_id mapping, scraper), but
the mixed architecture made each fix expose the next layer of mixing
complexity. Engineering effort was spent working around the architecture
rather than fixing actual problems.

### 08:15-08:45 - Spec: Semantic-Structural Split
Wrote [[semantic-structural-split]] spec. 5 phases:
1. Move factual oracles to assay (lexical, temporal, persona, belief)
2. First semantic domain — knowledge (beliefs + patterns + commits)
3. Consumer-level fusion (assay facts + scry meaning)
4. Eval redesign (test each layer independently)
5. Actively discover additional semantic domains

Key design decisions:
- Multi-domain semantic architecture: scry can have multiple semantic
  domains (knowledge, sessions, code), each with own model and training
  signal. BUT domains are earned through measurement, not declared by fiat.
- [[andrew-ng-over-shoulder]] applied to architecture: don't ship a domain
  unless it proves retrieval value over assay's factual search alone.
- The goal is to find AS MANY value-adding domains as possible — patina's
  competitive advantage IS semantic depth. Measurement is a quality gate,
  not a speed limit.
- Mother's cross-project semantic layer follows naturally once per-project
  domains validate.
- Apple ecosystem (Core ML, ANE, cross-device) noted as strategic direction
  that the multi-model architecture supports without closing doors.

### Patterns Observed
- **Architecture drives measurement quality** — the retrieval tuning loop
  wasn't a measurement problem, it was an architecture problem. Fixing
  measurement kept exposing architecture debt. The right fix is architectural.
- **Scry is the semantic layer, not a search engine** — reframing scry from
  "file retrieval" to "meaning layer" clarifies what it should and shouldn't
  do. Facts belong in assay. Meaning belongs in scry.
- **Domains are earned, not declared** — applying [[andrew-ng-over-shoulder]]
  to architecture itself. Don't build a 5-domain system because it looks good.
  Build one domain, prove it, then actively hunt for more.
- **Value imperative** — patina's competitive advantage is semantic depth.
  One domain is table stakes. The risk is too few domains, not too many.
