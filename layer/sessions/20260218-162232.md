**Work completed:** Deep adversarial review of [[spec-launcher-tmux]] SPEC.md.
Started from the draft tightened last session and iterated through 5 rounds
of gap analysis covering ~20 specific issues. Spec grew from 47 lines of
design to 277 lines — every edge case, failure mode, and testability concern
addressed. Promoted draft → ready → active. Wrote continuation prompt for
implementation session.

**Key decisions:**
- Session name: `patina_<slug>_<hash>` using FNV-1a 32-bit (8 hex chars).
  No adapter name in session name — YAGNI since adapters enforce single
  instance per project. Discussed with user after external agent proposed
  multi-session framework; concluded it's moot given adapter constraints.
- `TmuxDecision` enum with `OffReason` (6 variants) instead of simple bool.
  Pure function `resolve_tmux_decision()` takes 6 bool params for testability.
  Caller pairs context (version string) with reason for targeted warnings.
- exec() semantics: honest about what's catchable (OS-level failures only).
  Dropped false "two-stage catches everything" promise. Runtime tmux errors
  are tmux's problem — user sees tmux output and uses `--no-tmux`.
- `tmux -V` version probe for ≥ 1.9 (`-c` flag). Proactive detection so
  users on old systems get helpful message, not cryptic tmux error.
- Non-UTF-8 safe: `.arg(OsStr)` for tmux `-c` path, `to_string_lossy()`
  for slug, raw `as_encoded_bytes()` for hash.

**Challenges faced:** Iterative spec review surfaced cascading design gaps —
each fix revealed new edge cases (exec semantics invalidated fallback
promises, pure function couldn't emit warnings without richer return type,
hash needed exact algorithm specification). Required careful re-reading of
spec after each round to find stale references and contradictions.

**Patterns observed:** Adversarial spec review before coding is extremely
valuable — caught 20+ issues that would have been bugs or contradictions in
code. The [[dependable-rust]] pattern of "small stable interface" maps well
to spec design: each function signature in the spec IS the interface
contract. Read all 4 layer/core design docs before reviewing — they
grounded every decision.
