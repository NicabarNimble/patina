### 13:25 - Secrets subsystem discovery sweep
User asked to explore how Patina secrets work. Launched a thorough Explore agent to map the subsystem end-to-end. Key findings:

**Architecture**: Mother owns all crypto. CLI is a thin dispatcher — operations go over IPC (UDS or HTTP+bearer token via `PATINA_SERVE_TOKEN`). Child processes never touch the identity. See `crates/patina-protocol/src/lib.rs:100-145` for `SecretsAuthorityOperation` enum.

**Storage — two scopes, three file types**:
- Vaults: `~/.patina/vault.age` (global) + `.patina/vault.age` (project), age-encrypted TOML blob `HashMap<String,String>`
- Registry: `~/.patina/secrets.toml` + `.patina/secrets.toml`, plaintext `name → ENV_VAR` mapping
- Recipients: `~/.patina/recipients.txt` + `.patina/recipients.txt`, age public keys (multi-recipient → team sharing)

**Identity — 3-tier fallback** (`mother/src/secrets_authority_backend/`):
1. `PATINA_IDENTITY` env var (highest priority)
2. `~/.patina/identity.enc` — ChaCha20Poly1305 + HKDF, machine-locked via IOPlatformUUID / `/etc/machine-id`. PATINA magic header + version + salt + nonce + ciphertext. Atomic temp-file-rename writes.
3. macOS Keychain (legacy, auto-migrates to encrypted file on read at `storage.rs:48-61`)

**Vault encryption**: age x25519 asymmetric, ASCII-armored, multi-recipient for team sharing. Cannot remove last recipient (safety check at `mod.rs:230`).

**Injection path**: `patina run -- CMD` → `src/secrets/mod.rs:66-95 load_secrets_via_ipc()` → Mother's `load_secrets_env_map()` at `mod.rs:259` → merged env map → `process.env_all()`. Session cache in `patina serve` daemon (UDS → TCP fallback, 10-min TTL) avoids repeated Touch ID prompts (`src/secrets/session.rs`). SSH mode pipes `export VAR='val'` via stdin — never hits remote disk (`src/secrets/mod.rs:37-64`, with single-quote escaping + tests at :147).

**Naming convention** (`registry.rs:101-146`): secret names are lowercase-hyphenated (`github-token`), env vars are uppercase-underscored (`GITHUB_TOKEN`), mapping is inferred by default.

**Scanner / leak prevention** (`src/scanner/mod.rs` + `src/commands/secrets.rs:564-596`): pattern-based detection for AWS keys, GitHub tokens, private keys, etc. `patina secrets check` is a pre-commit hook that blocks commits; `patina secrets audit` scans all tracked files. Respects `.secretsignore`.

**Claude OAuth special case**: stored as global secret `claude-oauth` → `CLAUDE_CODE_OAUTH_TOKEN`. Guided flow at `src/commands/secrets.rs:517 setup_claude()` validates the `sk-ant-*` prefix and handles replacement transparently. Used by launcher for headless/SSH/tmux sessions.

**Gaps identified (no implementation found)**:
- No per-child/per-toy capability model — all secrets land in every toy's env via `wasi:cli/environment`
- No SDK-level secrets API — `sdk/patina-sdk` exposes nothing; only IPC
- No rotation, expiration, versioning, or audit trail (who-read-what-when)
- No redaction in error messages or tracing output
- No integration tests for Mother → child injection or team vault round-trips
- No `spec-secrets-*`, no architecture doc in `layer/core/`
- Only one belief on the topic: [[connection-secrets-live-in-global-vault]] (traced to 2026-03-07 broker lookup failure)

**Stated philosophy** (header comment `src/commands/secrets.rs:1-4`): *"Local-first secrets: age encryption + macOS Keychain + Touch ID. LLMs never see secret values."*

## Handoff
Secrets subsystem is architecturally sound for local-first offline use but has real gaps worth naming as future work. Candidate threads if the user wants to push on any of them:

1. **Capability model for child access** — WIT interface that gates which secrets a toy can see; would require Mother to mediate per-component, not per-process. This is the biggest design gap and aligns with the component-model direction from [[session-20260409-143847-707078000]].
2. **SDK surface** — give `patina-sdk` a typed secrets API so toy authors don't reach through env vars. Natural fit with [[spec-sdk-public-surface-alignment]] / [[sdk-is-mct-entry-point]] from the previous sessions.
3. **Rotation / lifecycle / audit** — add `expires_at`, rotation command, audit log of access events.
4. **Write the missing spec** — no `spec-secrets-*` exists; lots of implicit architecture worth making explicit before the next refactor touches it.
