3. **Runtime Secret Exposure** (deepest thread):
   - User asked: "isn't env var injection insecure?" — YES
   - `run_with_secrets` injects ALL vault secrets as env vars into child process
   - LLM can `env | grep CARGO` and see cargo registry token it never needs
   - Compared with IronClaw's WASM boundary — tools never see secrets, host injects at HTTP boundary
   - User pointed out: "the whole point was to protect from LLM seeing secrets"
   - **The contradiction**: We encrypt at rest, protect decryption key... then inject plaintext as env vars
   - User asked about making secrets command a WASM plugin — proposed host-boundary injection architecture
   - User challenged: "how is this different from IronClaw?"
   - **Critical discovery in IronClaw's proxy** (line 246-248): HTTPS CONNECT tunnels CAN'T inject credentials — IronClaw falls back to env vars for HTTPS too
   - Cloudflare Workers also give plaintext to the worker that consumes it
   - **Industry-wide gap**: Nobody has solved "hide credential from HTTPS consumer" — Bearer tokens require plaintext
   - User's key insight: "the API key unlocks the LLM, not LLM unlocks self" — auth is transport layer, not LLM layer
   - User asked about encrypted keys in transit — pointed to Secure Enclave, AWS Sig V4, mTLS as models
   - Proxy architecture proposed but HTTPS limitation makes credential injection impossible without MITM

**Key decisions:**
- **Ship Phase 1 as-is**: Dual-storage is real value (SSH fixed, at-rest encryption, machine-binding)
- **Phase 2 = try/fallback**: Option C (try Keychain, fall back to encrypted file) — simplest, no detection logic
- **Scoped injection is the quick win**: Don't inject cargo key into claude process (~10 lines in launcher)
- **Domain allowlisting is the real security**: Even if LLM sees key, can't exfiltrate to evil.com
- **Full credential isolation requires API protocol change**: Bearer tokens are the industry constraint, not our architecture
