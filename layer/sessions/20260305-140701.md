Created `plugins/forge/` with 4 files:
- `Cargo.toml` — cdylib with patina-sdk (mother-child), serde, serde_json
- `plugin.toml` — world=mother-child, role=connector, host_http=[api.github.com], host_emit=true, host_secrets for Bearer token
- `src/lib.rs` — `ForgeChild` implementing `MotherChildPlugin` with `sync` and `resolve` actions
- `src/github.rs` — `GitHubClient` with REST API parsing, per_page pagination, 750ms rate limiting

Key design decisions:
- GitHub REST API uses snake_case (unlike gh CLI's camelCase) — different serde structs needed
- HttpResponse has only `status` + `body` (no headers) — pagination via per_page+page counting instead of Link headers
- Issues endpoint includes PRs — filter by `pull_request` field being present
- Event JSON format matches existing scrape format for compatibility (`number`, `title`, `body`, `state`, `labels`, `author`, `url`, `updated_at`)
- `linked_issues` empty for now (REST API doesn't expose `closingIssuesReferences` — that's GraphQL)
- `tick()` is a stub — ref discovery needs host infrastructure (session 2-3)
