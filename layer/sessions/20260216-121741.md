**Key decisions:**
- **No new beliefs yet** — design principles (beliefs-vs-values, projects-are-islands, etc.)
  parked in [[mother-design]] SPEC as draft, not captured as beliefs. User wants to decide
  later whether to build or abandon.
- **Extend `mother graph sync`, don't add new command** — same registry walk, same
  `Graph::open()`, one more table. Avoids command naming collision.
- **New `mother` MCP tool + extend `context`** — per [[mcp-is-shim-cli-is-product]], each
  MCP tool wraps CLI library functions. `mother` is the 4th atomic tool. `context` is the
  composition layer that combines all three search tools + layer files.
- **`context` as tunable composition** — token budget can be controlled by adjusting how much
  from each source. Future refinement scope, not this SPEC.

**Patterns observed:**
- Validating SPECs against actual codebase catches architecture mismatches early. The original
  Phase C (add mode to scry) would have forced a project-scoped tool to do cross-project work.
- The CLI/MCP symmetry pattern (same Rust library, two interfaces) was already established by
  scry and assay — extending it to mother is natural, not novel.
- `context` as composition layer is an emergent pattern worth formalizing — it's already doing
  this for scry + assay, adding mother is just one more ingredient.
