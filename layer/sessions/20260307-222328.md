**Key Discovery — Projection Gap:**
The github-connector emits `github.issue`/`github.pr` events to events.db, but `project_from_events()` in `events.rs` hardcodes `WHERE event_type = 'forge.issue'`. GitHub-connector data is invisible to `scry --include-issues` and `assay`. This is the critical finding — user lost searchability of GitHub issues/PRs when the forge pipeline was deleted.

**Discussion with external agent** about ForgeWriter:
- ForgeWriter is used by init flow (`ensure_fork`) and repo contrib flow (`create_fork`)
- It bypasses the pipe architecture — shells out to `gh` CLI directly
- Should be replaced by pipe verbs routed through the github child
- But `grammars/forge/` and `wit/schema/forge/` are reference implementations for the replacement — don't delete yet
