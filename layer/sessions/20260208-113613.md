**Key decisions:**
- **Knowledge corpus = beliefs + patterns + commits only.** Session events (32K, 92% of old index) excluded — they polluted the vector space with session co-occurrence signal. Code facts excluded — structural data belongs in assay.

- **SemanticOracle auto-detects domain.** Prefers `knowledge.usearch` if present, falls back to `semantic.usearch`. No config change needed in oracle — it finds what's available.

### Patterns Observed
- **Read-before-write pays off.** Reading all 10+ files first revealed the ID offset system in enrichment, the ref repo backward compat need in `oxidize_for_repo()`, and the stale "Hybrid RRF" label. All of these would have caused bugs or missed cleanups without upfront reading.
- **92% pollution → 5% signal.** The old index was 92% session events. Removing them dropped the index from ~35K to 1,903 items and immediately produced non-zero eval results. The problem wasn't the model or training — it was the corpus composition.
- **Additive-then-switch** works better than additive-then-reductive for renames. Phase 1 used additive-then-reductive (add assay features, then remove from scry). Phase 2 used additive-then-switch (add `"knowledge"` type, then switch recipe/paths). The switch approach is cleaner when you're renaming rather than moving.
