**Key Decisions:**

1. **wasmtime over Extism** — Zed uses wasmtime, production-proven, Component Model support
2. **Separate worlds per plugin type** — Diverging from Zed for stricter isolation (oracle plugins can't see HTTP)
3. **Scoped threads first** — Use `std::thread::scope` for plugin calls, preserves borrowing, no async infection
4. **Contained tokio only if needed** — If scoped threads don't scale, add tiny tokio runtime (2 threads) contained to one module

**Patterns Observed:**

- [[sync-first]] is compatible with WASM plugins if async is contained to host layer
- "If you scope the async part tighter than the whole program, your life will be better"
- Zed's `gpui_tokio` bridge is a clean containment pattern
- Static lifetime infection only happens with unscoped `spawn`
