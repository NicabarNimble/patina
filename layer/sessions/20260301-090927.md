**Structural audit of Patina codebase against 8 LLM-generated Rust failure modes.**

Started from an external "structural audit spec" prompt designed to detect "architecture-shaped code without invariants." Rather than generating a generic spec document, ran the audit against Patina itself using 3 parallel agents scanning `src/` (216 files, 73k LOC):

*Agent 1 — Type soup:* Found the dominant issue. MCP server handlers use `serde_json::Value` with 400+ `.get("key")` chains, 200 total type soup operations concentrated in `src/mcp/server/scry.rs` (103), `spec.rs` (81), `assay.rs` (16). Also found 78 operations in `src/commands/measure/internal.rs`.

*Agent 2 — Module structure:* Only 1 glob re-export (`pub use *`) in all of `src/`. 53 targeted re-exports, 69 `pub(crate)` usages. Clean encapsulation following [[dependable-rust]] module pattern. 7 OnceLock usages all justified (wasmtime engine, etc). No circular deps.

*Agent 3 — Validation/errors:* 2 custom error types + anyhow everywhere (intentional for CLI). 9 validate functions at boundaries. Scoring weights well-documented as named constants. BeliefEntry (23 fields) is intentional materialized view. 338 `.unwrap()` mostly in tests, ~10 in production.
