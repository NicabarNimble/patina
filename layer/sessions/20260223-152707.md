**Work completed:**

Reviewed two external documents that influence [[spec-workflow-rigor]] design:

1. **"Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?"** (Gloaguen et al., ETH Zurich, Feb 2026) — rigorous evaluation of CLAUDE.md/AGENTS.md impact on coding agents. Key finding: context files *reduce* task success rates while increasing cost 20%+. LLM-generated files hurt (-3%), developer-written help marginally (+4%). But when docs are absent, context files help (+2.7%). Instructions are followed — the problem is unnecessary requirements make tasks harder. Recommendation: minimal requirements only.

2. **Anthropic Skills Guide** — official guide for building Claude skills. Three-level progressive disclosure (frontmatter → SKILL.md body → references). Description field is the most important part (WHAT + WHEN triggers). Category 2 (Workflow Automation) maps to our `/spec` skill design.

Applied the "Evaluating AGENTS.md" findings immediately: trimmed `CLAUDE.md` from 155 → 44 lines ([[commit-50e7af6c]]). Cut all inline documentation the LLM can discover by reading code or running `patina --help` (architecture, project structure, key commands, design philosophy). Kept behavioral rules (git discipline, testing, CI) and pointers to where knowledge lives.

**Discussion context:**
- User challenged whether the three docs (SPEC + design + walkthroughs) were bloat. Answered with consumer analysis: each doc serves a different reader at a different time. This held up.

- "Evaluating AGENTS.md" paper prompted rethink of CLAUDE.md approach. Patina is a special case (custom conventions not in training data) but the "minimal requirements" principle still applies. Cut the overview, kept the rules.

**Key decisions:**
- **CLAUDE.md = rules + pointers, not documentation.** Behavioral constraints the LLM must follow, plus links to where knowledge lives. Everything else is discoverable. 134 lines deleted.
