**Work completed:**

Implemented [[spec-data-db-split]] end-to-end — all 7 spec steps in a single
focused session. Spec lifecycle: draft → ready → active → complete (v0.33.1).

*Infrastructure (`src/eventlog.rs`, `src/measure.rs`):*
- Added `EVENTS_DB` constant, `ensure_events_db()` migration function, and
  `open_events_db()` convenience function with WAL mode + synchronous=FULL
- One-time migration uses ATTACH internally: events.db ATTACHes patina.db to
  copy 96 runtime events in a single SQL statement. Idempotent on re-run.
- `measure::emit()` signature simplified — removed `conn` parameter, opens
  events.db internally. Updated all 7 callers across 5 files.
- Deleted `create_feedback_views()` dead code (~130 lines of unused SQL views)

*Runtime writers (scry, MCP, forge):*
- `src/commands/scry/internal/logging.rs` — all 5 logging functions now write
  to events.db via `eventlog::open_events_db()` instead of `PATINA_DB`
- `src/mcp/server/scry.rs` — `log_mcp_query()`, `handle_use()` write to
  events.db; `handle_detail()` reads scry.query from events.db + content
  from patina.db (cross-database read pattern)
- `src/commands/scrape/forge/mod.rs` — `insert_issues()`/`insert_prs()` take
  dual connections: events_conn for eventlog + dedup, patina_conn for
  materialized views. 4 callers in `extract_v2.rs` updated.

*Rebuild + readers:*
- `execute_rebuild()` only deletes patina.db, adds `ensure_events_db()` call
- `measure/internal.rs` uses ATTACH pattern: open patina.db → ATTACH
  events.db AS events → prefix measure.* queries with `events.eventlog`

*Gate test:* `rm patina.db && patina scrape` — count before (96) = count
after (96 migrated + 1 new measure.capture = 97). Runtime events survive.

**Key decisions:**
- `measure::emit()` self-contained (no conn param) — matches scry logging
  pattern, simplifies callers, 7 call sites cleaned up
- Forge uses explicit dual-connection rather than ATTACH — clearer ownership
  (eventlog vs materialized views) and avoids ATTACH scope confusion
- Measure uses ATTACH — per-request pattern per DESIGN.md, graceful fallback
  if events.db doesn't exist (returns empty/0 instead of erroring)
- `ensure_events_db()` called from both write path (open_events_db) and read
  path (measure run) to guarantee migration happens on first use regardless
  of which command runs first

**Patterns observed:**
- The "read all code before writing" mandate paid off — understanding the
  forge dual-write pattern (eventlog + materialized views) upfront prevented
  a naive single-connection approach that would have broken forge dedup
- Single-commit implementation was feasible because all 7 steps are tightly
  coupled — splitting would have left the system in broken intermediate states
