## Decisions

- **Observability ownership:** Each layer observes the layer below at the boundary, never inside. Mother owns infrastructure telemetry (automatic), children optionally emit domain signals via `measure` toy. Captured as [[observation-at-the-boundary]].
- **WASI-first toy surface:** Build with WASI, not parallel to it. Standard interfaces used directly, custom toys cover only the delta. Custom interfaces follow WASI conventions for upstream contribution. Captured as [[wasi-is-foundation-not-option]].
- **Focused children are the default:** One responsibility, narrow toybox, composable. Composite children are a prototyping stage, not an alternative philosophy. Component Model composition handles tight-coupling edge cases.
- **Parent/child spec structure:** [[spec-child-construction-canon]] is the constitution (hard rules, recipe format). Three child specs own implementation: [[spec-folder-text-to-parquet]], [[spec-e2ee-multimother-chat]], [[spec-multiproject-belief-share]].
- **Build order:** wasi-toy-alignment → folder-text-to-parquet (+ canon in tandem) → multiproject-belief-share (tighten canon) → e2ee-multimother-chat (multi-Mother proof) → SDK extracted from all three.
- **Two-tier measurement contract:** Mother-guaranteed metrics (lifecycle, latency, throughput, errors) are free. Child-declared domain metrics via `measure` toy are optional, declared in manifest, cardinality-bounded.
- **8 hard rules locked in canon:** authority boundary, explicit grants, least-privilege, append-only truth, idempotent reruns, provenance, observation-at-boundary, WASI-is-foundation.
- **WASI toy audit results:** 3 migrate (log→wasi:logging, state→wasi:keyvalue, store→wasi:sql), 1 extend (events→wasi:messaging + patina:events-stream delta), 1 keep (connect as HTTP authority delta), 1 new (measure, no WASI standard exists).
