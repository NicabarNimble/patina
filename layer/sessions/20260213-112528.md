**Key Decisions:**
- **QueryDispatchFn callback pattern** — Spec assumed `QueryEngine` lives on `CommandHostState`. Can't: plugin system is in lib.rs, retrieval/commands are in binary crate. Solution: lib defines the port (gating + sanitization), binary supplies the adapter (closure with engines). Classic hex architecture. Stronger than original spec because it cleanly separates policy from wiring.
- **Defense in depth layering** — Load-time: `check_capabilities()` rejects unknown query kinds. Call-time: grants check denies ungrated kinds. Data-level: `sanitize_query_params()` strips scope-reserved keys before callback sees them. Three independent layers.
- **Reserved scope keys** — Not just `all_repos` but also `repo`, `project_root`, `db_path`. Host-controlled keys that plugins must not rely on being preserved. Prevents future bypass vectors.

**Challenges Faced:**
- Binary/library crate boundary was the main obstacle. `crate::commands::*` and `crate::retrieval::*` resolve in main.rs but not from `src/plugin/` (lib.rs). Solved with callback injection — zero refactoring of module boundaries.
- WIT files copied across 6 locations (canonical + 5 plugin crates). Discovered `patina-command-api` has its own copy, not a symlink. Had to sync all copies for guest-side bindgen to find the new query interface.
- Old doctor WASM fixture (pre-query WIT) still works with new host — wasmtime component model is backward compatible for unimported interfaces. Updated fixture anyway for CI.

**Patterns Observed:**
- **Callback injection > module restructuring** when crate boundaries block direct references. Keeps blast radius zero on existing architecture.
- **Extracted testable functions** (`sanitize_query_params`) from wasmtime Host trait impls enable unit testing without WASM infrastructure.
- External agent review caught a real gap: scope enforcement was only at control-flow level (return Err), not data level (strip keys). Adding data-level sanitization is strictly stronger.
