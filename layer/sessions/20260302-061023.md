### 06:15 - Note [patina@7144b68b]
Key structural comparison: QMD is a document search engine (markdown files → chunks → hybrid search). Patina is a knowledge protocol (git events → enriched items → semantic search). QMD focuses on one thing well (search quality via 3-model pipeline), Patina covers 5 verbs (capture, index, search, believe, evolve). QMD's hybrid search pipeline (BM25 probe → query expansion → parallel retrieval → RRF → reranking → position-aware blending) is significantly more sophisticated than Patina's separate scry/assay approach.

### 06:16 - Note [patina@7144b68b]
Session 1 complete. Key takeaways for Session 2 mapping: (1) Query expansion — Patina has none, QMD's typed lex/vec/hyde with fine-tuned model is biggest gap. (2) Hybrid fusion — Patina keeps scry/assay separate, QMD fuses them with RRF. (3) Reranking — QMD's chunk-then-rerank with position-aware blending is elegant, Patina has none. (4) Smart chunking — QMD's break point scoring with code fence protection vs Patina's content-aware composition. (5) Context annotations — hierarchical path metadata, simpler than beliefs but solves discoverability. (6) MCP instructions — dynamic server instructions from index state. (7) Strong signal short-circuit — skip expensive ops when BM25 is confident.
