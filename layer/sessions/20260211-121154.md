**Discussion context:**

Major strategic conversation about spec sprawl. 32 specs is a governance failure — the system designed to bring clarity created fog. Key insights:
- "explore" type became a junk drawer for ideas that aren't action contracts
- v1-release was a meta-roadmap that went stale (version numbers meaningless after spec-driven versioning)
- Even the AI couldn't draw the core/plugin boundary — proving the bible is needed FIRST
- User's key insight: don't triage specs, let the plugin system build triage them. Build the plugin system, consume useful parts from frozen specs, archive whatever's left.

**Key decisions:**

- **Bible before specs** — core identity pattern (like [[dependable-rust]] or [[unix-philosophy]]) defines what Patina IS and ISN'T. This defines the core/plugin boundary.
- **Plugin system is THE priority** — WIT/WASM via wasmtime. The plugin boundary IS the identity definition.
- **Mother children ARE plugins** — MotherChild trait is the precursor to WIT interfaces. mother-environment and mother-repos are "first plugins," not separate specs.
- **Hard freeze, not triage** — all specs frozen to design. Plugin build selectively consumes them. Remaining noise gets archived after.
- **Major releases (1.0.0) explicitly require human decision** — `--major` flag is deliberate, not automated.
- **Remove "explore" type after plugin system ships** — explorations belong in sessions and beliefs, not specs.

**Patterns observed:**

- **Spec hoarding mirrors code bloat** — the same [[transparent-complexity]] principle applies: complexity you can't see will kill you. 32 specs is invisible complexity in the governance layer.
- **Stale blockers went undetected** — eval-repair and mother-architecture were archived but 4 specs still referenced them as blockers. The spec system needs its own safeguards (which is what [[spec-drift-detection]] proposes, ironically as a frozen spec).
- **The work triages the specs** — instead of spending a session triaging 30+ specs, use the actual build to determine what's valuable. If a frozen spec has content useful for the plugin system, it gets consumed. If not, it was noise.
