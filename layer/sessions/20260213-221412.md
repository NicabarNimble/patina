**Key Decisions:**
- **PipelineHostState = name + wasi only.** Spec was clear — pipeline is the simplest world. Strictly log-only. No design hesitation.
- **UTF-8 source in envelope, not base64.** Source code is text — no need for encoding overhead. Avoided adding `base64` as a new direct dependency.
- **Plugin-first dispatch with fallback.** `process_file_with_plugins()` checks plugin map by file extension, falls through to `process_file_by_language()` on miss or error. Matches [[graceful-extraction]] pattern.
- **Serde derives on database types.** ExtractedData and all component types now have Serialize/Deserialize. Spec anticipated this ("verify Serialize derive exists — if not, add it as part of commit 3"). Purely additive, no breaking changes.
- **Added Default to PluginProvides.** Clean way to handle new fields (pipeline_ops, languages) without updating 18+ test constructor sites individually — `..Default::default()` pattern.

**Patterns Observed:**
- **Four-world symmetry is fully established.** `mod.rs` now exports four engines (PluginEngine, CommandEngine, TaskEngine, PipelineEngine). Each follows the same shape: bindgen module + HostState + Host trait impls + Engine struct with new() + load + handle/run.
- **Spec-driven implementation remains mechanical.** The 10-file read list + 4-commit plan from [[plugin-pipeline-world]] SPEC.md left zero ambiguity. ~20 minutes from first read to all tests passing.
- **Pipeline is the simplest world by design.** Where task world was command + HTTP + toys, pipeline strips everything except log. This validates [[separate-worlds-for-isolation]] — each world gets exactly the capabilities it needs.
