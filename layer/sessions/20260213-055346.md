**Key Decisions:**
- The query host interface should use the MCP server's existing JSON-in/string-out pattern — one `query(kind, params)` function, not N typed interfaces per feature. Extends the "string dispatch within worlds" philosophy to host functions
- Query access should be available in both worlds (mother-child + command), capability-gated via manifest
- Install path should support three sources: local crate (LLM workflow), GitHub repo (sharing), pre-built WASM (distribution)
- Skill registration should happen at plugin install time, not compile time — plugins ship skill markdown alongside WASM
- Design spec is a vision document (what/why); existing Phase 3-5 specs remain the implementation docs (how)

**Patterns Observed:**
- The MCP server (`src/mcp/server.rs`) already provides the exact boundary needed for WASM query access — JSON dispatch to QueryEngine, assay, context. No new engines needed, just a WIT wrapper
- The `repo` command's registry pattern (`registry.yaml`, clone, scaffold) is a direct blueprint for `patina plugin install`
- Existing guest API crates aren't on crates.io — this is a blocker for LLM-authored plugins since LLMs need `cargo add` to work

- Commits: [[08c60337]] protocol governance refinements, [[7b6be0a1]] initial spec + beliefs

**Key Decisions:**
- Pipeline world is pure compute only — all side effects (fs, model loading, network) pushed into host. This prevents pipeline becoming a junk drawer. Compile-time isolation via WIT, not runtime enforcement.
- Task world added as 4th world — covers "on-demand action" gap (PR reviewer, one-shot deploy). Command stays toyless for psychological safety ("commands inform, they don't act").
- `patina:host/http` with domain allowlisting replaces raw `curl` toys for webhooks. Toy system stays for local processes (git, cargo, wrangler).
- Query scope (`current_project | allowed_repos | all_repos`) is a manifest-level capability, not implicit.
- Adapters are a 5th extension point but outside the 4 WASM worlds — they need full host access (auth, APIs, secrets).
