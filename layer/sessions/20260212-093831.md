**Key decisions:**
- `unsafe impl Sync` is a soundness issue, not just style — generated types can change between wasmtime versions without warning
- CI check over symlinks for WIT consistency — symlinks break cargo publish, some CI, Windows
- Toy capability gating via manifest `[capabilities.toys].commands` allowlist, enforced in WasmChild::tick() — Option A (adapter-level) over Option B (daemon-level)
- String dispatch within worlds is documented as intentional, not accidental — per-child typed WIT variants would require per-child *worlds*, which is a different architecture
- No deferrals policy: if it's not blocked and not over-engineering, do it now

**Patterns observed:**

## Discoveries

1. **Design review with external perspective catches different things than audits** — the audit signed off on `unsafe impl Sync` as "sound"; the design review identified it as fragile (depends on generated type we don't control). Different lenses, different findings.

2. **Zed comparison is a powerful calibration tool** — comparing design decisions against a production system (77 WIT files, millions of users) either validates ("we diverged for good reason") or reveals gaps ("Zed solves this, we don't").

3. **"Deferred" is the default failure mode of audit findings** — without [[no-deferrals-without-blockers]], 3 of 5 discoveries would have sat as session notes until someone stumbled on them again.
