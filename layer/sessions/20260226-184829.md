**Key decisions:**
- Used `OnceLock<Result<(), String>>` not `OnceLock<()>` — caches initialization
  errors so they're reported on every call, not just the first
- Migration preserves original seq from patina.db (not AUTOINCREMENT) — makes
  `INSERT OR IGNORE` work naturally for both migration and import
- Doctor reads JSONL max seq by scanning last non-empty line in reverse — no
  need to parse entire file
- WASM doctor plugin takes priority over compiled-in — our checks exist in the
  fallback path, which is the correct architecture
