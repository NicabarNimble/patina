Per [[andrew-ng-over-shoulder]]: "measure the simplest thing first." Previous session identified next step as testing raw E5-base-v2 without projection. This is the foundational diagnostic — determines whether the projection adds value.

**Raw E5 diagnostic ([[e603121b]]):**
Added `patina eval --scry-raw` — brute-force cosine over raw E5-base-v2 (768-dim) embeddings without projection. Embeds entire knowledge corpus (615 items) + 20 eval queries with raw E5, computes cosine similarity, maps results back to doc_ids via same ID offset scheme as enrichment module. Made `query_knowledge_corpus` `pub(crate)` for reuse. Pre-computes all embeddings to avoid mutable borrow in `Fn` closures. 4 files, +279/-1.

**Results — the projection is catastrophic:**

```
                     Method      P@5     P@10      MRR     Hits
           Raw E5 (768-dim)    48.3%    52.5%    0.427    75.0%
        Projected (256-dim)     6.7%     9.2%    0.072    15.0%
```

- 12/20 raw-only hits, 0/20 projection-only, 3/20 both hit, 5/20 both miss
- Raw E5 already bridges vocabulary gaps: "ripple effects" → [[dependable-rust]], "baselines before optimization" → [[andrew-ng-over-shoulder]], "test contamination" → [[never-tune-on-eval]]
- The trained 2-layer MLP compresses 768→256 dim and **scrambles** the useful structure from E5 pre-training
- Also exceeds Phase 4 criterion: 15/20 total hits (target was ≥5/20 scry-only)

**Key insight:** Every Phase 5a-5d "improvement" to the trainer (corpus optimization, gradient fix, belief pairs, determinism) was polishing a component that should be deleted. The base model was always capable — we were training noise on top of it.

**Next step identified:** Remove projection for knowledge/sessions domains in `oxidize` and `SemanticOracle`. Use raw 768-dim E5 embeddings directly. Implementation was started but interrupted — prompt for continuation drafted.

**Key decisions:**
- Built the diagnostic as a separate `--scry-raw` flag (not modifying `--scry`) since it's slow (~60s embedding 615 items)
- Pre-computed all query embeddings to work with `&dyn Fn` closures (avoids `&mut` borrow issue with `embed_query`)
- Used same ID offset constants as enrichment module for key→doc_id mapping

**Patterns observed:**
- [[andrew-ng-over-shoulder]] validated: "measure the simplest thing first" found a 43pp improvement that all prior architecture work missed
- [[corpus-composition-over-model]] partially wrong assumption: the model (raw E5) was always good — the projection was the problem, not the corpus. Corpus optimization from Phase 5a still valid though.
- Complexity penalty: the MLP projection added complexity that destroyed existing capability. Simpler (raw embeddings) was dramatically better.
