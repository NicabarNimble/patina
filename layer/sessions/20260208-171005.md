**Baseline results:**
- Assay eval: P@10 38.0%, MRR 0.473, 64% hit rate (25 factual queries)
- Scry eval: P@10 25.0%, MRR 0.193, 35% hit rate (20 conceptual queries)
- Scry-vs-assay: 4/20 scry-only hits (target ≥5, 1 short)
- Combined eval: P@10 31.9%, MRR 0.319, 60% hit rate (45 total queries)

**Key decisions:**
- **New query sets, not patched old ones** — per [[never-tune-on-eval]], the existing 52 NL queries were designed for the mixed-oracle era with stale file paths (5 deleted oracle files). Created fresh query sets designed for the post-split architecture rather than patching the old ones. Old `nl-queries.json` preserved for historical comparison.
- **Scry queries use doc_id format** — expected results use the actual doc_id format scry returns: belief IDs (e.g., `dependable-rust`), pattern file paths (e.g., `layer/core/dependable-rust.md`). Discovered during code reading that belief enrichment returns raw ID, not `belief:{id}` prefix — the old eval's `belief:` prefix matching was broken post-split.
- **Independent modules per [[dependable-rust]]** — new eval code lives in `src/commands/eval/internal/` without touching the existing 1,511 lines in `mod.rs`. Smallest blast radius: add new capability, don't refactor working code.
- **Scry-vs-assay criterion not met (4/20 vs 5/20)** — reported honestly per [[andrew-ng-over-shoulder]]. Root cause diagnosed: knowledge index is commit-dominated (~1,851 commits vs ~157 beliefs+patterns). E5-base-v2 maps conceptual queries to commit messages rather than beliefs/patterns. Scry succeeds when query vocabulary overlaps belief text (4 hits: error-analysis, corpus-composition, measure-first/measure-the-measurement), fails on large vocabulary gaps (9 both-miss queries). Not an eval bug — genuine model+corpus limitation.

**Patterns observed:**
- **Read-first discipline scales** — reading 12+ files and 3 parallel exploration agents before writing meant zero surprises during implementation. Every design decision (doc_id formats, expected result formats, module structure) was informed by actual code, not assumptions.
- **Scry's value is real but narrow** — 4/20 scry-only hits proves semantic search adds value for belief-heavy conceptual queries where FTS5 can't bridge vocabulary gaps. But the 9 both-miss cases show the model can't bridge LARGE gaps. Improvement requires better training signal or model, not more eval infrastructure.
- **Retrieval-tuning Phases 3-5 cleanly map to assay** — the split makes these problems simpler. Belief score multiplier, hub suppression, and product metrics are all assay-internal concerns now. No cross-system coupling.
