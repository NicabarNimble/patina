### 13:50 - Key Discovery: Grammars Are NOT the Simplest Payload

Used `patina scry` and `patina context` to retrieve history on why we compile C code directly. Found sessions [[20250901-135830]], [[20250901-164140]], [[20250824-113703]]:
- tree-sitter 0.24 expects ABI 13-14, C/C++ grammars generate ABI 15
- Solidity grammar pins us to tree-sitter 0.24
- Solution was vendor-and-pin: raw `parser.c` compiled via `cc::Build`
- **This ABI coupling applies equally to WASM grammars**

Also discovered tree-sitter 0.24 has a `wasm` feature (uses `wasmtime-c-api-impl` internally), but since we need `wasmtime` directly for Phases 2-5, using tree-sitter's wasm feature would mean learning an API we'd never use again.

### 14:05 - Architecture Decision: Option C (PluginEngine Shared)

User asked fundamental question: what is Mother's role in the plugin system? Explored three options:
- Option A: Spec as-is (PluginHost + Mother separate) — two loading paths
- Option B: Everything under Mother — requires daemon for basic commands (regression)
- **Option C: Shared PluginEngine** — wasmtime guts shared between Mother (daemon, resident children) and CLI (one-shot commands). Mother adds lifecycle (load, tick, health, toys). CLI doesn't need Mother running.
