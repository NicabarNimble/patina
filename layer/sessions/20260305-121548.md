### 13:00-13:30 - Advisor Review
Ran advisory board review (Jon Gjengset, Andrew Kelley, Eskil Steenberg, Pat Helland). Key criticisms:

1. **Gjengset: schema parsed from disk on every emit** — 500 issues = 500 disk reads. Fix: cache at load time. **User: DO THIS.**
2. **Gjengset: string error erasure** — `Result<u64, String>` loses error identity. User decided: skip EmitError enum. At WIT boundary, types can't be preserved. Consistent with [[gjengset-lens-type-integrity]] belief's "whenever possible" qualifier + prior session note about spec cargo-culting typed errors.
3. **Kelley: event_type indirection** — plugin could send event_type directly. User: wants ZERO TRUST from plugins. Host resolves event_type from authoritative schema. No change.
4. **Kelley/Eskil: payload wrapper redundant** — `_provenance`/`_schema`/`_plugin` metadata wrapping payload nests data unnecessarily. `source_id` already carries provenance (`plugin:<name>`), `event_type` carries schema (`forge.issue`). Wrapper creates downstream shape mismatch. Fix: write data directly.
5. **Eskil: metadata should be columns** — cart before horse. [[spec-data-architecture-v3]] (blocked by [[spec-plugin-infrastructure]], ~2 sessions away) will add proper `provenance` column. Defer.
6. **Helland: seq number is local** — valid but premature. Cursor/checkpoint use case is real. [[seq-order-is-not-timestamp-order]] already documents locality. No change.
7. **Streaming compatibility confirmed** — emit-fact per-event works for request/response, polling, AND future WebSocket/streaming (Mother buffers → tick() → batch parse → emit per event). Schema caching helps streaming (no per-event disk reads).
