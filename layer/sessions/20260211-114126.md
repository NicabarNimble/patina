**Work completed:**

1. **Fixed safeguard dirty-tree sequencing** ([[commit-88e7c721]]) — live testing `patina spec status mother-architecture complete` revealed that the spec file itself dirties the tree before preflight runs. Fix: thread `spec_path` through `preflight()` → `run_safeguard_checks()` so the file being released is excluded from the clean-tree check. This is [[compiler-enforced-safety]] in action — the API now requires you to declare what you're releasing.

2. **Excluded untracked files from safeguards** ([[commit-de543ce7]]) — `git status --porcelain` includes `??` untracked files. These are harmless (not in the release commit). Filter them out. Old `spec status complete` had zero safeguards so this was never caught before.

3. **Completed [[mother-architecture]]** ([[commit-6cee7c1f]]) — `patina spec status mother-architecture complete` → feat → minor bump → 0.15.3 → 0.16.0. Full end-to-end test of the new `ReleaseStrategy` path with safeguards. Tag `v0.16.0` created. All 6 ACs from mother-architecture are implemented (commits [[commit-ebb40612]] through [[commit-3abbe869]] in prior sessions).

**Key decisions:**

- **Exclude spec_path, not skip the check** — could have committed the status change separately (two commits) or skipped the dirty-tree check entirely. Chose to exclude only the known-dirty file, preserving the safeguard for everything else. Transparent: the API makes you say what you're releasing.
- **Untracked = harmless** — `??` files in porcelain output are never staged, never committed. Including them in the dirty-tree check was overly strict. The old `version milestone` code had the same `is_clean()` call but was never triggered because `spec status complete` had zero safeguards.

**Patterns observed:**

- **Live testing catches what walkthroughs miss** — the session-20260211-100430 walkthrough found zero safeguards but didn't predict the spec-file-dirties-itself problem. Only running the real command revealed it. Always test with `cargo install --path . && patina <command>`.
- **Safeguards need to understand their own context** — a safeguard that blocks on state it created is worse than no safeguard. The fix (threading spec_path) makes the safeguard context-aware without weakening it.
