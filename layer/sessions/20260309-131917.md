**Work completed:** Complete rewrite of [[spec-patina-connect]] SPEC.md and DESIGN.md, elevating patina-connect from a CLI convenience feature to a product subsystem with three layers.

1. **Full auth/secrets audit** — Inventoried all 5 auth/credential systems in the codebase: vault (secrets/), plugin credential injection (WASM path), broker credential delivery (native child path), Mother daemon auth, Claude OAuth token. Grounded every design claim in existing code.

2. **Three-layer architecture** — Designed with input from an external audit agent:
   - **Acquisition**: per-provider credential obtainment (Provider trait)
   - **Persistence**: connection domain model (ConnectionRecord with identity + auth metadata)
   - **Consumption**: `resolve_auth()` → AuthPlan (the seam between durable metadata and runtime)

**Key decisions:**
- **Persistence is the center**, not acquisition. Build model-out, not feature-in.
- **Dispatch on auth strategy, not provider.** Broker asks "Bearer? Header? InProcess?" — never "GitHub? Slack?"
- **Storage / Domain / Runtime separation.** Storage owns durable TOML (no secrets). Domain owns validation + `resolve_auth()` (the only vault decryption point). Runtime owns AuthPlan execution.
- **Fail closed on auth-required children.** `resolve_auth()` returns error when credential missing. Replaces `broker/mod.rs:44-48` "proceeding without auth" warning — a fail-open violation of the `child.toml auth.required` contract.
- **Sever broker plugin imports.** `broker/http.rs:12-13` imports `CredentialMapping` and `InjectionLocation` from plugin module. These serve the WASM security boundary, not native-child connections. Extract shared HTTP utils to `src/http_util.rs` — not copy.
- **Connections are global (user-level) in v1.** `ConnectionScope::Global` with commented future variants.

**Discussion context:** Extended discussion with external audit agent who identified the three-layer decomposition (Get/Store/Reuse → Acquisition/Persistence/Consumption), the two kinds of metadata (identity vs runtime auth), the `resolve_auth()` seam constraint ("broker should consume a resolved auth plan, not raw fields"), and the architectural drift audit (keep/move/fix/delete inventory).
