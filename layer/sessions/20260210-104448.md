**Q2: Who Are the Children?** — REFRAMED. User corrected: "stop trying to enumerate children." Children should be near-infinite — plugins like Obsidian. The question isn't "who are the 4 or 7 children" but "what is the plugin shape." Children are a Large Array of Things.

**Q3: Belief Ownership** — RESOLVED. Beliefs born in projects, can be promoted to Mother as user-level truths. Mother queries project beliefs on demand (read-only, no sync, no copy). Cross-project access: LLM searches project beliefs → asks Mother → Mother searches user beliefs + other projects + ref repos → returns grounded answer with provenance.

**Key architectural decisions made this session:**
1. Two things exist: projects and Mother
2. Children are plugins, not a fixed list — the shape is the expensive choice
3. Native Rust traits now, WIT worlds later, same shape
4. Mother is a plugin host with 5 responsibilities
5. Beliefs born in projects, promoted to Mother, queried on demand
6. `cache/` convention = rebuildable, each child declares its own state
